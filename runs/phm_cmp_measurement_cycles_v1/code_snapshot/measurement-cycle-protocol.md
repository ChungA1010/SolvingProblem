# 측정 주기 및 A/B 공유 추적 고정 계획

2026-09-29. 이전 개발 결과를 보고 설계한 후속 실험이다. 새로운 독립 Test나 kp_model v0.3 재현이 아니다.

1. team comparison v1의 시간순 fold 2~5와 최종 purge된 학습 목록을 그대로 쓴다. 주 평가 대상은 A456/B456 1,286개다. A123은 다른 테이블이므로 A/B 공유에 넣지 않는다.
2. 측정 예산은 ch4의 공정 시작 순서에서 매 1/5/10번째 **기록된** 공정을 측정하는 것으로 정의한다. A/B별로 각각 측정하여 예산을 두 배 쓰지 않는다. 처음 n번째를 측정하는 offset=n-1을 UI 기본으로 하며, 연구에서는 offset 0~n-1을 전부 평가한다. 실제 미기록 공정의 측정 주기와 같다고 주장하지 않는다.
3. 측정 공개 지연은 별도 축이다. delay=0은 전체 로그 종료 즉시, delay=5는 같은 테이블의 관측된 후속 완료 공정 다섯 개가 더 끝난 시점이다. 측정하지 않은 공정도 지연 시계의 완료 횟수에는 포함된다.
4. 학습 구간의 측정도 같은 예산·offset으로 줄인다. 정규화 기준은 학습 목록에 있고 최초 평가 시작 전 공개된 측정의 레시피별 평균만 사용한다. 두 추적 방식의 측정 목록·기준 평균·초기 이력은 같다.
5. 별도 추적은 레시피별 EWMA, 공유 추적은 y/recipe_train_mean의 EWMA를 테이블에서 공유한 후 query recipe의 학습 평균을 곱한다. alpha=0.4, adjust=True 고정. 센서/사용량을 회귀 계수로 넣지 않는다. 공정 전 이용 가능한 이력으로만 예측한다.
6. 정답은 available_at < query.start인 측정만 사용한다. 같은 웨이퍼의 앞선 A 공정 측정도 실제로 공개됐으면 공유 추적에 사용할 수 있다. query 자신의 MRR이나 미래 측정은 사용하지 않는다. 시작 시각과 측정 공개 시각이 같으면 다음 공정부터 사용한다.
7. 모든 query에서 예측을 남긴다. 오프라인 연구 MAE/RMSE는 측정하지 않은 행을 포함해 과거에 이미 알려진 정답으로 사후 계산한다. 그 정답을 상태 갱신에 쓰지 않는다. 실제 UI는 공개 측정 오차만 실시간 표시하고 전체 과거 정답 점수는 재생 완료 뒤 별도로 표시한다.
8. fold별 MAE 평균과 pooled MAE/RMSE를 구분한다. 대표 연구 결과는 모든 offset 평균, UI 기본 offset도 별도로 보고한다. 공유 이득은 같은 fold/주기/지연/offset에서 짝지어 계산한다. 네 fold에서 반대 방향 차이가 나는지도 보고한다. 평가로 alpha나 모델을 다시 고르지 않는다.
9. UI의 장비 상태 선택은 실제 기록 시기(네 fold) 선택이다. 현재 웨이퍼의 패드/드레서 사용량·관측 공정 간격은 표시하되 임의 교체의 인과 효과를 만들어내지 않는다. 회전/압력 효과나 물리 시간 초 단위 추정을 새로 구현하는 작업은 아니다.
10. Unity는 별도/공유, 주기, 지연, 교육용 alpha를 설정하고 다음 1/10개 공정, 자동 재생/정지, 초기화, 결과 비교 및 JSON 내보내기를 제공한다. 설정 변경 시 새 세션을 만들어 이전 상태가 섞이지 않게 한다. 예측에서 나온 값을 실제 측정으로 되먹이지 않는다.
11. API와 연구 스크립트가 같은 추적 엔진을 쓰되, 별도의 벡터 계산으로 예측·이력을 재검증한다. API는 미공개 정답을 응답에서 제거하며 재시도·세션 격리·미래값 변경·동일 웨이퍼 A/B를 테스트한다. 기존 v1 추론·분류는 유지한다.
