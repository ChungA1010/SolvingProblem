# P2 큰 오차·선형회귀 영향 진단과 제한된 비교 — 사전 계획

2026-09-19. 대상은 원문 조건 재구성 v2의 P2 통합 모델이다. 기존 13종 baseline과 후속 v1–v4를 보존한다.
Test와 원문 수치를 이미 여러 번 확인했고 이번 초기 진단에서도 일부 오류를 확인했다.
따라서 후속 개발 실험이며 새로운 독립 검증이나 저자 코드의 완전한 재현이 아니다.

## 초기 관찰과 질문

- P2 통합 Test MSE 7.0743이며 상위 오류 10건이 제곱오차의 약 31.4%다.
- LR Test MSE 351.1079 중 큰 오류가 Cond1에 집중된다. 한 표본의 LR 예측은 약 454.65, 실제는 78.64다.
- Cond1/2의 LR 통합 가중치는 약 5.37e-7/1.11e-8로 작고 Cond3은 약 0.01839다.
- 작은 사용량 표준편차·감소 기울기 특징에서 큰 선형 계수의 상쇄를 관찰했다.
  큰 계수만으로 오류 원인을 확정하지 않고 조건수·특징 기여·반사실적 출력 차이를 기록한다.

## 고정 비교 세 가지

1. `original`: 기존 P2 v2 통합 모델을 그대로 재사용한다.
2. `no_lr`: LR 가중치를 0으로 만들고 다른 네 가중치를 합계 1로 재정규화한다.
3. `ridge10`: LR만 표준화+Ridge(alpha=10)로 교체한다. alpha는 사전 고정하며 탐색하지 않는다.
   원래 20회 Monte Carlo CV의 같은 학습·검증 ID와 특징 선택을 사용해 Ridge 오차를 계산하고,
   원래 가중식 `(mean MSE + 3*SD)^(-3)`에 해당 열만 바꿔 통합 가중치를 다시 계산한다.

기존 SVR·Bagging·직접 이력 예측·특징 목록·다른 모델의 CV 오차를 고정한다.
Ridge 교체 효과는 선형 모델 및 그 오차에 따라 달라지는 통합 가중치의 결합 효과다.
단순 제거는 다른 모델 재학습을 수반하지 않는다. 범위 제한·이상치 추가 삭제·새 특징·새 이력 정책을 도입하지 않는다.
세 절차 중 Test 최저를 자동 채택하지 않으며 기존 API/Unity 모델은 교체하지 않는다.

## 데이터와 평가

- 원래 Train 1,977건, Validation/Test 각 424건. 같은 4개 극단 Train 표본 제외 정책을 유지한다.
- 기존 5개 웨이퍼/파일 연결 그룹 바깥 분할과 1,551/166/260건의 시간순 학습/평가/경계 제외 분할을 유지한다.
- 5바깥+1시간순+1최종 × 3조건 = 21개 조건 적합. 원래 부모 학습 집합 모델을 재사용한다.
- 내부는 원래 20회 wafer 그룹 무작위 분할이다. CV끼리 평가 표본이 반복될 수 있으며 독립 20회 Test가 아니다.
- 원래 이력은 raw usage 이웃과 prior-start lag이며 미래 Train 이웃을 허용한다.
  완료된 과거 공정 전용 robust v2의 8.9491과 이번 값을 같은 조건의 순위로 비교하지 않는다.
- 바깥 그룹의 파일·웨이퍼 분리와 별도 시간순 평가를 확인한다. 원래 내부 CV의 파일 분리는 추가하지 않는다.
- 모든 신규 학습은 Train만 사용한다. 최종 모델·설정을 봉인한 뒤 Validation/Test 예측을 저장하고 정답을 결합한다.
- MSE/RMSE/MAE/R²/RE 및 조건별·Stage별 결과를 전체 표본에서 보고한다.
  오류 상위 10건의 결과는 진단용이며 채택 기준이 아니다. 오류를 이유로 표본을 삭제하지 않는다.

## 진단과 검증 산출물

- 기존 LR의 스케일링된 계수, 특이값·절단된 rank·유효 조건수, 선택 특징 간 높은 상관을 기록한다.
- 모든 Test/Validation 표본의 구성 모델 예측·가중 기여·LR 제거 효과·이력 가용량·입력 범위 이탈을 기록한다.
- 오류 상위 10건의 특징별 선형 기여와 원래 이력 참조 ID·시각을 추적한다.
  원시 로그의 품질 캐시를 연결하되 실제 계측 구간 대응까지 확정한 것으로 표시하지 않는다.
- 원래 예측과 모든 부모 모델 가중치가 보존됐는지, 원래 CV LR 오차를 다시 적합해 재현하는지 확인한다.
- 신규 Ridge의 전처리가 각 내부 학습 부분에서만 적합되는지, 조회 정답/순서 변경에 예측이 불변인지 검사한다.
- 보고서·모델·예측·지표·해시와 테스트를 기존 GitHub 브랜치에 게시한다. 원시 데이터와 중간 캐시는 게시하지 않는다.

```powershell
python -m cmp_ml.lr_ablation prepare
python -m cmp_ml.lr_ablation train
python -m cmp_ml.lr_ablation evaluate
python tools/verify_lr_ablation.py
```

기존 reconstruction v2 및 improvement v1의 입력/부모 모델 캐시가 필요하다.
기존 run을 덮어쓰지 않으며 새 실행은 `--run-dir runs/my_lr_ablation`으로 만든다.
