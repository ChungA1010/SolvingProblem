# CMP 교육용 시뮬레이터 상태 추적 설계

2026-09-29. 제공 START_HERE·결정기록·columns.csv와 실제 전처리 검사, 같은 조건 모델 비교를 바탕으로 정리한 설계다. 이번 산출물은 설계서이며 기존 Unity/API의 동작이나 모델을 교체하지 않았다.

## 교육 과업과 화면

첫 화면에서 A456, B456, A123 레시피와 과거 기록 시나리오를 고른다. 각 시나리오에는 최초 상태를 만들 과거 측정값, 소모품 카운터, 관측 시각, 공정 순서가 함께 들어간다. 빈 상태에서 임의의 최근 MRR을 생성하지 않는다.

| 화면 영역 | 학생이 보는 내용 | 동작 |
|---|---|---|
| 공정 조건 | 레시피, 압력 설정 묶음, 회전 고정값 | 레시피별로 관측된 설정 묶음을 선택한다. 서로 같이 변한 메인/센터/엣지 압력을 독립 효과로 해석하지 않는다. |
| 장비 상태 | 패드·드레서 사용 상태, 마지막 측정 후 경과, 관측이 빠진 공정 수 | 상태가 오래될수록 근거 부족을 설명한다. 소모품 교체는 카운터 재시작 사건으로 처리하고 개선 효과를 보장하지 않는다. |
| 측정 실험 | 측정 갱신 여부, 공개 지연, 측정 주기, 추적 가중치 λ | 고정된 기준 시나리오를 재생하며 조건을 하나씩 바꾼다. 측정 주기와 측정 지연은 별도 선택이다. |
| 결과 | 추정 MRR, 기준 대비 변화, 기준 대비 연마 시간 비율, 입력 근거 상태 | 실제 단위가 확인되지 않은 MRR을 nm/min 또는 µm/min으로 표기하지 않는다. |
| 기록 비교 | 실제 측정이 공개된 시점의 오차, MAE/RMSE, 측정 횟수 | 측정 전에는 정답을 보여주지 않는다. 학습 데이터 실험과 가상 시나리오를 구분한다. |

흐름: **시나리오 선택 → 과거 측정으로 초기화 → 다음 공정 예측 → 공정 완료 → 측정 공개 여부 확인 → 상태 갱신 → 다음 공정**.

## 변수별 처리

| 변수 | 1단계 정책 | 근거와 한계 |
|---|---|---|
| 레시피 | A456/B456/A123 선택 | 세 집단을 분리한다. A123에는 센서 기반 압력 조작을 제공하지 않는다. |
| 압력 | A456/B456별로 검증한 설정 묶음과 관측 영역 안에서만 제공 | 문서의 251~270은 대략적인 정상 영역이며 CSV 전체 최솟값/최댓값은 이상 구간을 포함한다. 모델 학습 구간의 레시피별 범위와 실제 설정 조합으로 허용 목록을 만든다. |
| 회전 | 레시피 값 표시, 조작 비활성 | 다른 회전·구간 구성과 함께 바뀌어 독립 효과를 추정하지 못했다. |
| 슬러리 C | 설명 또는 제한된 관측 시나리오 | 문서상 계수 신뢰구간이 0을 포함한다. 확정된 증감 효과를 표시하지 않는다. |
| 연마 시간·압력 적분 | 신규 센서 모델 입력에서 제외 | 상태 추적 교육 모델의 설계 방침이다. 기존 공정 종료 후 추정 논문 모델의 사용 자체가 무효라는 뜻은 아니다. |
| 긴 간격 | 관측 간격 / 실제 휴지로 추정되는 경우를 나눔 | 빠진 웨이퍼가 있으면 실제 정지 시간이라고 단정하지 않는다. |
| 드레싱 | 카운터 변화와 확인된 사건을 구분 | 카운터만으로 오프라인 드레싱을 확인할 수 없다. |
| λ | 기본 0.4, 교육 과업에서만 변경 | λ를 평가 점수가 좋아지도록 조절한 결과를 새 검증 성능으로 발표하지 않는다. |
| A/B 공유 추적 | 향후 별도 실험 기능 | 공유 패드라는 문서 해석은 참고한다. 서로 다른 평균 MRR을 그대로 섞지 않고 학습 자료로 정규화한 상태를 비교해야 한다. 이번 실험은 레시피별 추적이다. |

범위를 벗어나면 값을 몰래 자르거나 정상 신뢰도로 외삽하지 않는다. 입력은 유지하고 해당 결과에 `근거 부족`을 표시한다. 정상/범위 밖 판단에 평가 데이터의 최솟값·최댓값을 사용하지 않는다.

## 측정·상태 관리

- 키는 (wafer_id, stage)다. 같은 웨이퍼의 A/B를 서로 덮어쓰지 않는다. 테이블과 레시피를 별도로 저장한다.
- 실제 또는 재생 측정에는 `observed_at`, `available_at`, `measurement_id`, `source`가 필요하다. 같은 측정 ID를 재전송해도 상태를 두 번 갱신하지 않는다.
- 예측값을 자동으로 실제 측정처럼 다시 입력하지 않는다. 측정이 없으면 상태를 유지하고 상태의 나이·관측 수만 바뀐다.
- 시간 역행 측정은 기록에 보존하되 이벤트 순서대로 다시 재생하거나 오류를 반환한다. 현재 상태에 조용히 섞지 않는다.
- `frozen`은 평가 도중 새 측정이 없는 조건이다. `online`은 완료 즉시 결과가 공개된다는 가정이다. `delay5`는 데이터에 기록된 후속 공정 다섯 개가 더 끝난 뒤 공개하는 비교용 정의다. 실제 공장 5장 지연과 같지 않다.
- 학생이 바꾼 압력의 가상 공정에 과거 실제 정답을 그대로 붙여 평가하지 않는다. 과거 기록 재생 점수와 조작 시나리오의 추정 결과를 구분한다.

## 출력과 단위

기본 출력은 `MRR 상대 척도`와 같은 목표 제거량일 때의 `시간 비율 = 기준 MRR / 추정 MRR`이다. 추정 MRR이 0 이하이거나 유효 범위를 벗어나면 시간 비율을 내지 않는다.

실제 권장 시간(초)은 제거량과 MRR의 물리 단위·스케일이 검증된 뒤에만 제공한다. 단위가 맞으면 `시간(분) = 제거량 / MRR`, 이후 초로 변환한다. 단위 미확인 상태에서 목표 두께(nm)를 현재 MRR로 나눠 초라고 표시하지 않는다.

불확실성은 별도 보정 검증 전까지 숫자 신뢰구간으로 만들지 않는다. 대신 관측 영역, 상태 나이, 관측 수, 누락 센서를 설명한다. 문서의 MAE 2.63을 개별 예측의 ±오차로 사용하지 않는다.

## 기존 Unity/API에 연결할 변경점

현재 `CmpDemo.cs`는 A/B Stage와 정적 시나리오를 선택해 `/api/v1/predictions`를 호출한다. `runtime.py`의 시나리오 특징 대리값과 새 상태 모델의 입력 계약이 달라 별도 버전으로 도입한다.

| 제안 API | 역할 | 필수 필드/결과 |
|---|---|---|
| POST `/api/v2/state-sessions` | 재생 또는 교육 세션 시작 | recipe, table, scenario_id, alpha, measurement_policy, model_version |
| POST `/api/v2/state-sessions/{id}/predict` | 현재 공개된 상태로 한 공정 예측 | wafer_id, stage, event_time, recipe_setting_id, consumables; prediction_id, mrr_relative, state_age, support_status |
| POST `/api/v2/state-sessions/{id}/measurements` | 측정 공개 및 갱신 | measurement_id, wafer_id, stage, measured_mrr, observed_at, available_at, source |
| GET `/api/v2/state-sessions/{id}/timeline` | 예측·공정·측정·오차 순서 표시 | 기준 버전, 이벤트 순서, 공개된 정답만 포함 |
| POST `/api/v2/state-sessions/{id}/reset` | 최초 시나리오로 돌아감 | 초기 상태·이벤트 재생 위치 복구 |

Unity에는 레시피 선택, 상태 패널, 측정 시점 조절, 공정 진행/일시정지/초기화, 결과 비교 기록을 추가한다. 기존 웨이퍼 결함 분류 기능은 상태 추적과 인과적으로 연결됐다고 표현하지 않는다.

## 구현 완료 판단 기준

1. 같은 초기 상태·이벤트 목록·버전이면 동일한 예측이 나온다.
2. 늦게 공개되는 정답은 공개 전 예측에 영향을 주지 않는다. 중복 측정·시간 역행·동일 웨이퍼 A/B를 검사한다.
3. 미관측 압력 조합과 단위 미확인 시간 계산을 화면에서 구분한다.
4. 기록 재생 MAE/RMSE가 서버의 저장 예측으로 재계산한 값과 일치한다.
5. 새 후보 채택은 비교 보고서, 측정 가능 시점, 누락된 kp 모델 확인, 별도 미래 검증을 검토한 뒤 결정한다.

이번 모델 비교의 결과와 채택 판단은 [실험 보고서](../runs/phm_cmp_team_comparison_v1/README.md)에 연결한다. UI 구현이나 새 모델의 서비스 배포가 완료된 것으로 표시하지 않는다.
