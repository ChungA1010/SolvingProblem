# 팀 전처리 자료와 동일 조건 비교 계획

2026-09-29. 결과를 계산하기 전에 고정한 후속 개발 실험이다. 제공 자료와 이전 공식 Test는 이미 검토했으므로 새 독립 검증이라고 부르지 않는다.

- 제공 ZIP의 1,977개 (wafer_id, stage), 정답, 시간순 fold 1~5를 유지한다. fold 2~5를 차례로 평가하며 앞 fold만 학습한다. 평가 웨이퍼와 같은 ID 및 평가 시작 전에 전체 로그가 끝나지 않은 학습 행은 제거한다. 평가 행은 제거하지 않는다. 파일 연결 그룹 격리 실험과는 다른, 같은 장비의 미래 운전 평가다.
- A456/B456 공통 1,613행의 센서 모델을 주 비교로 하고 A123은 별도로 평균·직전값·EWMA를 비교한다. fold별 MAE의 단순 평균, 전체 평가 행의 pooled MAE/RMSE, 레시피별 점수, 압력 변경 포함/제외/변경만 점수를 보존한다.
- 원래 예제의 평균 7.18/EWMA 2.74는 별도 산술 재현한다. 수정 실험은 purge 및 측정 가능 시점이 달라 이 값과 같을 필요가 없다. kp_model.py/fit_kp.py가 없어 보정 모델 2.63은 미검증 참고값이다.
- 예측 이력은 모든 모델에 같은 원래 로그 start/end를 적용한다. 현재 공정의 센서 요약은 종료 후 가용하므로 센서 실험은 공정 종료 후 추정 성능이다. 이력 cutoff는 공정 시작이다. 이 결과만으로 공정 전 슬라이더의 인과 효과를 검증하지 않는다.
- frozen: 평가 구간의 정답을 이력에 추가하지 않는다. online: 앞선 공정의 전체 로그 종료 시 정답이 즉시 공개된다고 가정한다. delay5: 같은 테이블에서 관측된 5개 후속 공정이 추가로 끝난 뒤 공개한다. 빠진 웨이퍼 때문에 실제 공장의 5장 지연과 같다고 주장하지 않는다. 정답 공개 시점은 실제 측정 메타데이터가 없는 가정이다.
- 모든 모델은 fold 시작 시 한 번 학습하고 평가 중에는 가중치를 재학습하지 않는다. 세 조건에 동일한 학습 모델을 사용하며 지연 조건의 학습용 이력도 동일하게 지연 처리한다. frozen과 online은 같은 즉시 공개 학습 입력을 쓴다. 측정되지 않은 정답과 미래 정답은 입력으로 사용하지 않는다.
- 세 조건의 학습 표본도 같도록 delay5에서 fold 시작까지 정답이 공개되지 않은 마지막 학습 행은 모든 조건에서 함께 제외한다. 지연 조건의 학습 입력이 달라 해당 모델 계수는 별도로 적합한다.
- 기존 비교 모델: staged v4의 full125/primary73 RF 및 Bagging 구조를 새 분할에서 재학습한다. 100 trees, min_samples_leaf=5, max_features=0.7/1.0, bootstrap=True, seed 20260920/21/22 평균을 유지한다. 이전 모델 파일을 그대로 평가하거나 모든 논문 baseline을 다시 실행한 것으로 부르지 않는다.
- 신규 비교 모델: 허용된 숫자 조건 20개만 사용하는 RF/Bagging, 여기에 관측 가능한 EWMA·직전값·직전값 나이·추정 거리·관측 수를 붙여 EWMA 잔차를 예측하는 RF/Bagging. 고정된 동일 트리 설정을 사용한다. 하이퍼파라미터 탐색이나 평가 점수에 따른 재선택은 하지 않는다.
- EWMA alpha=0.4, adjust=True를 고정한다. 냉시작 대체값은 학습 레시피 평균이며, 신규 잔차 모델의 첫 5개 학습 행은 제외한다. 계산 편의를 위해 학습 행의 이후 값으로 EWMA를 초기화하지 않는다.
- 원본 185개 CSV의 해시를 기존 기록과 대조하고 제공 전처리의 물리 요약을 독립 재구성한다. 압력 평탄 ±2%, 슬러리 흐름 50%, 시간 간격 10초 상한은 자료의 정의를 유지한다. 장비 카운터 증가량, 레시피 중앙값, 결측 대체는 각 학습 fold에서만 추정한다. 빈 구간과 미관측 센서는 결측으로 유지한다.
- 입력에 금지된 시간/적분/정답/식별 플래그는 신규 모델에 넣지 않는다. 기존 125/73 모델은 기존 특징 구성을 유지하므로 교육용 입력 제한을 만족하는 모델로 부르지 않는다. 이 차이는 비교표에 명시한다.
- 측정 이력의 모든 참조 ID·가용 시점, 전처리 계수, 모델, 예측, 지표, 코드·입력 해시를 저장한다. 미래 행/정답 변경 불변성, purge, 기준 점수, 예측 재로딩을 검사한다. 기존 run과 API/Unity 모델은 보존한다.
- Unity 작업은 이번 결과를 반영한 설계서까지다. 제품 코드 변경·모델 교체는 이 요청의 범위가 아니다.
