## 플레이 흐름

1. 손님과 주문 대화를 나누고 의뢰를 받습니다. 일반 고객 3종과 가상의 특별 손님 2종이 있습니다.
2. 원판을 3D 장비로 드래그하고 압력·Wafer 회전·Stage 회전·Slurry C 유량·연마 시간을 설정합니다.
3. 가공한 웨이퍼를 측정기·보관 슬롯·바닥 폐기함으로 옮깁니다. 보관한 웨이퍼도 원하는 층에서 다시 꺼낼 수 있습니다.
4. 측정·정비는 주문당 추가 행동 2회 안에서 선택합니다. 무료 최종 검사 후 상자를 손님 앞으로 밀어 납품합니다. 부분 납품과 빈 납품으로도 주문을 마감할 수 있습니다.
5. 납품 반응과 다음 대화가 이어집니다. 세 주문이 끝나면 하루를 결산하고 장비·가구·환경 업그레이드를 구매합니다.

3D 접촉·회전·분리, 손님 반응, 부품 설명, 측정된 웨이퍼 정보, 모바일 조작, 튜토리얼을 제공합니다. 결과는 측정/검사 전에는 공개하지 않습니다. 실험 기록·검사 CSV·새로고침 복구 및 기존 5회 도전·학습 실험실·비교·과제 기능을 유지합니다.

## 최신 경제·조작 규칙

- 가공 전에 확정 비용을 표시합니다. 가공비는 기본료·시간·압력·회전·Slurry C 조건에 따라 달라지며 실행할 때 한 번 차감합니다. 예를 들어 기본 조건 121초는 12 P, Slurry C 150%는 14 P입니다.
- 첫 운영 자금 100 P에서 시작해 가공·측정·정비·납품 대금·구매가 같은 잔액에 반영됩니다. 주문/날짜 변경이나 새로고침으로 자금을 반복 지급하지 않습니다.
- 하루 결산은 매출·운영비·손익·구매·잔액을 구분합니다. 잔액 부족 시 조건을 충족하는 재도전 지원을 명시적으로 받을 수 있습니다.
- 기존 진행 중 주문은 이전 비용 규칙을 유지하고 다음 주문부터 새 규칙을 적용합니다. 이전 구매·소유권·기록을 보존합니다.
- 장비 강화는 구매 즉시 설치 연출과 외형에 반영되며, 계산 효과는 다음 주문부터 적용합니다. 가구는 지정된 작업대/벽/바닥 위치에 배치되며 계산 성능을 바꾸지 않습니다.
- 드래그 시작·정상 안착·취소를 구분하고, 정상 동작에 짧은 합성 효과음을 재생합니다. 설정에서 소리를 끌 수 있으며 선택은 저장됩니다. 모션 감소 설정과 소리 없는 환경에서도 진행할 수 있습니다.

모든 비용과 효과는 **교육용 게임 수치**입니다. 압력 등 원본 센서 값의 물리 단위를 임의로 붙이지 않습니다.

## 개발 및 검증

```sh
npm ci
npm run build
npm test
```

`npm run build`는 Three.js 장면과 Tailwind CSS를 빌드합니다. 현재 204개 자동 테스트가 통과했습니다(게임/실험실 198개 + 보존한 모델 연결 클라이언트 6개). 모델 연결 테스트는 요청·응답 계약을 검사하며 실제 Python 모델 서버의 성능 검증은 아닙니다.

[브라우저 플레이 기록](tests/browser-playthrough-report.json)에는 드래그·3회 주문·결산·구매·다음 날·복원·모바일 화면의 검증 결과가 있습니다. 효과음은 스케줄링·설정·오류 격리를 검사했으며 실제 스피커에서 음색과 음량을 청취 평가한 것은 아닙니다.

| 위치 | 내용 |
| --- | --- |
| `dist/game-model.js` | 가공 계산·조건별 비용·주문 상태·이벤트 복구 |

Blender 제작 상세는 [공방 모델 안내](model-source/workshop-catalog/README.md), [모델 QA](WORKSHOP-MODELS-QA.md), [작업대 QA](WORKBENCH-FLOW-QA.md)를 참고하세요. 이전 QA 문서는 당시 버전의 검사 기록이며 최신 검증은 위 플레이 기록을 기준으로 합니다.

기록은 브라우저 로컬 저장소에 보관되며 계정 간 동기화하지 않습니다. `server.mjs`는 로컬 미리보기 서버입니다. 공개 웹 배포와 별도 Python 모델 배포는 구분합니다.
