# CMP 연마 장비 시뮬레이터 (Issue #6)

`dist/lab-sim.html` — PHM 2016 실제 운전 기록(fold 5, 14일, A456·B456 327장)을 재생하는 장비 운영 시뮬레이터다.
학생은 상태 추적 모델의 예측을 보고 연마 시간을 정하고, 연마 중 경보에 대응하고, 계측 여부를 결정한다.
웨이퍼의 결과는 교육용 가정 수식이 아니라 **실제 측정값**에서 나온다.

## 실행

재생 데이터는 데이터 공개 범위가 결정될 때까지 저장소에 넣지 않는다(`.gitignore`). 처음 한 번 로컬에서 만든다.
저장소 루트에서 Python 3.12 + numpy/pandas/scikit-learn 환경으로 실행한다.

```powershell
python -m tools.lab_sim.build_lab_data --wafer-table <preprocessed_audit_source/preprocessed/wafer_table.csv> --traces <Dataset/CMP1/CMP-data/training>
cd ui-redesign
npm run preview   # http://127.0.0.1:8510/lab-sim.html
```

`build_lab_data`는 세 파일을 만든다.

| 파일 | 내용 | 커밋 |

| `dist/lab-sim/data/replay.json` | fold 5 웨이퍼 순서·사건·실측 MRR·연마 챔버 센서 기록, fold 4 끝의 상태 | X (로컬 전용) |

## 화면 구성

CMP Lab 디자인 토큰(밝은 배경, 흰 카드, `#0d6efd`)을 따른다.

- **위:** 4단계 안내(연마 시간 정하기 → 연마 진행 → 계측 결정 → 결과 확인)와 "지금 할 일" 문구
- **가운데:** 팀 3D 연마부(`cmp-scene.js`, `scene-model.js`, `scene-parts.js`)를 그대로 불러온다. 실제 센서 기록으로 접근·접촉·분리, 패드·헤드 회전, 압력에 따른 패드 압축, 슬러리 유량을 구동한다. 팀 파일은 수정하지 않는다. WebGL을 쓸 수 없으면 2D 도식으로 대체한다.
- **오른쪽 메뉴:** [운전] 예측과 연마 시간·종료 시간 조정·계측 결정, [계측 설정] 계측 주기·결과 도착·대기열, [과제 안내]
- **아래 결과:** 실시간 공정 데이터(게이지·압력 추세), 예측 상세, 장비 상태·알람, 관리도, 운전 기록

## 모델 (상태 추적 v2)

레시피별로 "정상 압력 기준 제거 속도"를 칼만 필터로 추적한다.

- **투입 전:** 직전 같은 레시피 웨이퍼의 압력을 계획 압력으로 보고 MRR과 90% 구간을 예측한다.
- **연마 중:** 관측된 주 압력으로 (p / p_ref)^α 보정을 한다. A456은 α=1(Preston, 학습 구간에 압력 이상이 없어 물리 기본값)을 쓴다. B456은 학습 우도가 α=0을 골랐으므로 경보만 표시하고 보정하지 않는다.
- **측정 대기:** 측정되지 않은 웨이퍼는 상태를 바꾸지 않는다. 그만큼 다음 예측 구간이 넓어진다.
- **측정 후:** 압력을 정규화한 값으로 상태를 갱신한다. 휴지 후·패드 교체 후 첫 장은 일회성 보정을 한다(실제 자료에서 효과가 첫 장에만 나타남).

개발 fold 평가에서 투입 전 정확도는 Ridge v1과 통계적으로 같았다(채택 규칙 미통과). 시뮬레이터에 쓰는 이유는 기능 때문이다: 예측 구간, 측정 지연·드문 측정 처리, 연마 중 보정. 자세한 내용은 [평가 보고서](../runs/lab_sim_state_model_v2/REPORT.md)에 있다.

## 화면에 표시하는 데이터와 가정의 구분

- **실제 기록:** 웨이퍼 순서, 휴지·패드 교체, 연마 챔버 센서(1초 간격), 실측 MRR
- **모델:** 예측 MRR, 90% 구간, 상태 추정, 연마 중 보정
- **가정:** 제거량 = 실측 MRR × 연마 시간, 목표 = 기준 MRR × 기준 시간, 규격 ±5%. 본 연마 구간은 정한 시간에 맞춰 늘이거나 줄여 재생한다. 값은 원시 단위다(물리 단위 미확인).

실제 제거량은 계측 전까지 보여주지 않는다. 계측하지 않은 웨이퍼의 결과는 운전이 끝난 뒤 결과 창에서만 공개한다.

## 검증

```powershell
node --test tests/lab-sim-*.test.cjs
```

- 모델 일치 4개, 엔진 9개 테스트를 둔다.
- 엔진 테스트는 합성 웨이퍼와 합성 센서 기록을 쓰므로 재생 데이터 없이 실행된다.
- 헤드리스 Edge로 과제 선택 → 수동 연마 → 연마 중 경보(B456 W140, A456 W147) → 자동 R2R → 결과 창, 그리고 390px 모바일 화면을 확인했다. 콘솔 오류는 없었고 가로 넘침도 없었다.
- 이 검증은 기능 동작 확인이며 교육 효과나 독립 예측 성능 검증이 아니다.
