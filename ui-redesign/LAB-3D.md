# 학습 실험실: 3D 연마 장비 직접 조작 (Issue #6, 실험 브랜치)

`dist/lab-3d.html`은 3D 연마 장비의 부품을 **직접 끌어서** 산화막 한 장을 연마해 보는 화면이다. 홈 화면의 `학습 실험실`이 이 화면을 연다. 값을 입력하고 시작 버튼을 누르는 방식이 아니라, 연마가 실시간으로 진행되는 동안 헤드·플래튼·밸브를 손으로 움직인다. 기존 장비 시뮬레이터(`lab-sim.html`, [LAB-SIM.md](LAB-SIM.md))와는 별개이며, 그쪽 코드는 건드리지 않는다.

## 열기

`dist/lab-3d.html`을 더블클릭한다. 서버와 데이터 파일이 필요 없다(WebGL 2 필요). 홈 화면(`dist/index.html`)에서는 `학습 실험실` 카드가, 게임 화면에서는 설정 메뉴의 `학습 실험실`이 이 화면으로 온다.

한 파일 빌드(`node tools/build-standalone.mjs` → `standalone/CMP-Lab.html`)에도 들어 있다(`#lab-3d`).

## 홈 화면

`dist/index.html`의 모드 선택 화면은 두 모드를 나란히 세운 화면이다. 각 모드를 꾸밈 그림 대신 자기 장면의 실제 그림으로 보여 주고, 그 아래에는 누구를 위한 것인지, 이름, 한 문장, 그 모드에만 있는 사실 하나(게임의 첫 의뢰, 실험실의 산화막 색 눈금), 시작 단추만 둔다. 카드, 배지, 아이콘, 그라데이션은 쓰지 않는다. 스타일은 `dist/home.css`에 있다.

- 모드 선택 화면이 떠 있는 동안에는 안쪽 화면용 틀(왼쪽 메뉴, 위쪽 줄, 제목)을 숨긴다. 숨겨 둔 안쪽 화면을 주소로 열면 그 틀이 다시 나온다.
- 게임 그림 `dist/media/home/factory.webp`는 게임의 그림 세 장(방, 손님, 카운터)을 게임과 같은 순서로 겹쳐 만든다: `python tools/build-home-art.py` (Pillow 필요).
- 실험실 그림 `dist/media/home/lab.webp`는 실제 3D 장비가 연마하는 장면을 헤드리스 브라우저로 찍은 것이다: `node tools/render-lab-still.mjs` (Node 22 이상, Edge나 Chrome 필요). 3D 장비의 모양을 바꾸면 다시 찍는다.
- 산화막 색 눈금은 `dist/home.js`가 실험실의 계산 모델(`lab-3d/process-model.js`)로 그린다. 들어오는 두께에서 목표 두께까지의 실제 간섭색이다.

## 홈 화면에서 숨겨 둔 것

홈 화면에는 팩토리 게임과 학습 실험실 두 가지만 보인다. 아래 진입점은 지우지 않고 `hidden data-parked` 두 속성으로 숨겼다. 화면과 코드는 그대로 있고 주소(`index.html#lab` 등)로는 여전히 열린다. 되살리려면 해당 요소에서 두 속성을 지운다.

| 숨긴 것 | 위치 |
|---|---|
| 예전 학습 실험실 워크스페이스 (`#lab`) | 홈 카드 단추, 왼쪽 메뉴, 모바일 메뉴 |
| 데이터 기반 MRR 예측 (`#prediction`) | 왼쪽 메뉴, 모바일 메뉴, 홈 안내 줄 |
| 실험 기록 (`#history`), 학습 가이드 (`#guide`) | 왼쪽 메뉴, 모바일 메뉴. 둘 다 예전 워크스페이스용이다 |
| 장비 시뮬레이터 (`lab-sim.html`) | 홈 안내 줄 |
| 3D 실험판 안내 줄 | 홈 안내 줄. 카드가 같은 곳으로 가므로 겹친다 |
| 기존 5회 MRR 도전 (`#intro-tour`, `#intro`) | 홈 각주, 게임 설정 창의 링크 |
| 팩토리 게임, 학습 실험실 링크 | 왼쪽 메뉴, 모바일 메뉴(메뉴 전체). 카드와 겹친다 |

한 파일 빌드는 숨겨 둔 장비 시뮬레이터를 기본으로 뺀다. 그래서 기본 빌드에는 시뮬레이터의 PHM 재생 데이터(`replay.json`)가 들어가지 않는다. `node tools/build-standalone.mjs --all`은 시뮬레이터와 재생 데이터까지 넣는다(그 파일의 공유 범위는 예전과 같다).

## 화면

한 화면이다. 3D 화면 아래에는 아무것도 없고, 3D 화면 위에도 글자를 거의 두지 않는다. 정보는 필요한 순간에 3D 화면 안으로 나온다.

- **항상 보이는 것:** 막 두께 계기(현재 두께, 목표까지 남은 양, 작업 지시 세 항목), 다음 조작 한 줄, 시점 버튼. 경보는 생겼을 때만 나온다.
- **부품 정보:** 부품에 마우스를 올리면 그 부품에만 카드가 뜬다. 이름, 하는 일, 현재 값, 조작법이 나오고, 웨이퍼를 누르고 있는 동안에는 그 부품이 정하는 제거 속도 요인과 근거(교과서 식 / 단순화 가정)도 나온다. 조작할 수 없는 부품(계측기, 장비 화면, 신호등, 슬러리 공급 암, 압력 게이지, 로드 위치)도 카드가 있다.
- **끄는 동안:** 카드 대신 지금 정하고 있는 값만 부품 위에 나온다.
- **장비 화면:** 장비에 달린 터치 패널이 두께, 다운포스, 회전수, 슬러리, 패드 온도, 제거 속도를 보여 준다. 누르면 가까이에서 본다.
- **공정 계기 (아래 띠):** 웨이퍼가 패드에 닿으면 아래에서 올라오고, 웨이퍼가 헤드를 떠나면 내려간다. 막 두께 추이와 제거 속도 추이, 제거 속도와 여섯 요인, 반경별 두께와 균일도, 패드 온도와 경보선이 나온다. 요인 막대는 가운데 선이 기준(×1)이고 파랑은 느려지는 쪽, 주황은 빨라지는 쪽이다. 그래프에 마우스를 올리면 그 시점의 값이, 요인에 올리면 식의 근거가 나온다. 왼쪽 아래 단추로 직접 펴고 접을 수 있고, 한번 접으면 자동으로 다시 올라오지 않는다.
- **계측 리포트 (오른쪽):** 계측이 끝나면 열린다. 판정, 기준 대비 막대(평균 두께, 균일도), 49점 두께 지도와 반경별 두께, 같은 값의 표, 결과 풀이, 연마 기록(두께 추이, 연마하는 동안의 평균 조건, 결과 수치)이 한 장에 있다. `기록` 탭에는 계측한 웨이퍼가 쌓이고(최대 12장, 새로 고치면 사라짐), 한 줄을 누르면 그 웨이퍼의 리포트가 열린다. 닫은 뒤에는 막 두께 계기의 `계측 기록`으로 다시 연다.
- **화면 이동:** 띠나 리포트가 열리면 3D 화면의 중심이 남은 공간으로 옮겨 가서 장비가 가려지지 않는다. 확대 배율은 그대로다.

그래프는 한 그래프에 한 계열만 그린다(축 두 개를 겹치지 않는다). 색은 세 가지 뜻으로만 쓴다: 파랑은 그 그래프의 값, 파랑↔주황은 기준보다 작음↔큼(요인 막대, 두께 지도), 초록/빨강은 통과/미달이며 항상 기호와 글자가 함께 붙는다. 파랑·주황 조합은 색각 이상 구분 검사(프로탄·듀탄·트리탄)를 통과한 값이다.

## 조작

부품 위에서 휠을 굴리면 조금씩 바뀐다. 빈 곳을 끌면 시점이 돌고, 휠로 확대한다.

| 부품 | 조작 | 바뀌는 값 |
|---|---|---|
| 웨이퍼 | 끌어서 헤드 아래 / 계측기 / 로드 위치에 놓기. 헤드에 있을 때는 헤드를 끝까지 올린 뒤 옆으로 끌어낸다 | 위치 |
| 플래튼(패드) | 원을 그리듯 끌기 (시계 반대 방향이 가속) | 0~150 rpm |
| 헤드 스핀들 | 좌우로 끌기 | 헤드 회전 0~150 rpm |
| 구역 압력 조절기 (스핀들 앞 다이얼) | 좌우로 끌기 (오른쪽이 웨이퍼 가운데) | 가운데/가장자리 ±15% |
| 슬러리 밸브 (빨간 핸들) | 오른쪽·위로 끌기 | 0~400 mL/min |
| 컨디셔너 | 누르기 | 쓸기 / 대기 |
| 헤드 | 아래로 끌어 접촉, 더 끌어 가압. 위로 끌면 반대 | 간격 0~120 mm, 다운포스 0~7 psi |
| 비상 정지 | 누르기 | 회전·슬러리 정지, 헤드 올림 |

작업 지시는 하나다: 산화막을 550 ± 25 nm로 남기고, 웨이퍼 안 균일도(49점, 1σ) 3% 이하, 스크래치 0개. 들어오는 웨이퍼마다 막 평균(약 1,000 nm)과 프로파일(가장자리가 두껍거나 가운데가 두꺼움)이 다르다. 계측 뒤 두꺼우면 다시 헤드에 올려 이어서 연마할 수 있다. 안내 문구는 다음에 할 수 있는 조작만 알려 주고 값은 알려 주지 않는다. 안내가 가리키는 부품에는 주황색 표시가 뜬다.

## 계산

`dist/lab-3d/process-model.js` (DOM·3D와 무관, Node에서 테스트). 웨이퍼 반경 31개 지점의 막 두께를 실시간으로 깎는다.

```
제거 속도(r) = 기준 250 nm/min × 압력(r) × 속도(r) × 슬러리(r) × 패드 × 온도 × 접촉
```

| 요인 | 내용 | 근거 |
|---|---|---|
| 압력 | Preston 식. 가장자리는 패드가 되튀어 더 눌리고(압력이 높을수록 큼), 구역 압력 조절기가 가운데와 가장자리 사이로 압력을 옮긴다(면적 평균은 그대로) | 교과서 식 + 단순화 |
| 속도 | 플래튼·헤드 회전에서 나오는 상대 속도의 한 바퀴 평균. 두 회전수가 같으면 웨이퍼 전체가 같고, 다르면 가장자리가 빠르다. 헤드가 돌지 않으면 한쪽만 깎여 기운다 | 교과서 식(기구학) |
| 슬러리 | 패드 젖음(유량으로 차고 회전으로 빠짐)에 따라 포화. 모자라면 가운데부터 덜 깎이고, 거의 마르면 긁힌다 | 단순화 가정 |
| 패드 | 연마할수록 무뎌지고 컨디셔너가 되살린다. 컨디셔닝은 패드를 닳게 한다 | 단순화 가정 |
| 온도 | 마찰열 ∝ 마찰계수 × 압력 × 속도, 슬러리가 식힌다. 제거 속도에는 Arrhenius 식 | 교과서 식 |
| 접촉 | 속도에 비해 압력이 낮으면 수막 위에 떠서 깎이지 않는다 | 단순화 가정 |

- 막 색은 SiO₂/Si 박막 간섭을 계산한 것이다(수직 입사 Fresnel 반사 → CIE 색). 목표 두께 550 nm가 초록색으로 보인다. 화면에서 잘 보이도록 채도를 올렸다.
- 막 두께 모니터는 플래튼 1회전마다 한 번, 잡음이 섞인 값을 읽는다. 헤드는 압력이 빠진 뒤에 올라가므로 올리는 동안에도 조금 더 깎인다.
- 값은 대표적인 300 mm 산화막 CMP 조건을 가정한 것이며 이 장비의 실측값이 아니다. **PHM 2016 데이터로 학습한 장비 상태 모델은 아직 연결하지 않았다.** `create({ level })`이 그 자리다.

## 파일

| 파일 | 내용 |
|---|---|
| `dist/lab-3d.html`, `dist/lab-3d/lab-3d.css`, `dist/lab-3d/app.js` | 화면, 막 두께 계기, 부품 카드, 장비 화면 그리기, 공정 계기 그래프, 계측 리포트와 기록 |
| `dist/lab-3d/process-model.js` | 공정 계산 |
| `src/lab-3d-scene.js` → `dist/lab-3d/scene.js` | 3D 장면과 끌기 조작. `tools/build-lab3d.mjs`가 묶고, 어떤 원본에서 만들었는지 `dist/lab-3d/scene.build.json`에 적는다 |
| `tests/lab-3d-process.test.cjs` | 계산 테스트 14개 (합성 입력만) |
| `tests/lab-3d-bundle.test.cjs` | 번들이 지금의 원본에서 만들어진 것인지 확인 |
| `tools/check-browser.mjs`, `tools/headless-browser.mjs` | 헤드리스 브라우저로 화면을 실제로 써 보는 검사 |

3D 장비는 외부 모델 없이 기본 도형으로 만든다(팀 3D 모델은 쓰지 않음). 그래서 모든 부품이 움직인다. 구성은 플래튼 하나짜리 연구용 연마 장비를 따랐다: 스테인리스 작업대와 스플래시 볼, 뒤쪽 유틸리티 벽과 캐노피, 벽에서 나온 오버암과 스핀들, 벨로즈 아래의 캐리어 헤드, 슬러리 밸브와 유량계, 컨디셔너와 세정 컵, 로드 컵, 두께 계측기. 헤드 다운포스 게이지 바늘, 유량계 부표, 신호등, 장비 화면은 계산 값을 따라 움직인다. 공급 공기 게이지와 조작부 버튼, 배관 포트는 장식이다. 치수는 300 mm 장비에 그럴듯한 값이며 실제 장비 도면이 아니다. 라벨의 `CMP LAB CMP-01`은 지어낸 이름이다.

`scene.js`는 three.js를 포함한 번들이다. 장면을 고친 뒤 다시 만든다. 다시 만들지 않으면 `tests/lab-3d-bundle.test.cjs`가 실패한다.

```sh
node tools/build-lab3d.mjs
```

npm이 있으면 `npm run build:lab3d`도 같다. npm이 없는 PC에서 쓰는 법과 고친 뒤 돌릴 검사는 [MAINTENANCE.md](MAINTENANCE.md)에 있다.

## 확인하는 것

아래는 명령으로 매번 다시 확인할 수 있다. 명령과 고친 뒤 돌릴 순서는 [MAINTENANCE.md](MAINTENANCE.md)에 있다.

- `node --test tests/lab-3d-process.test.cjs`: 기준 조건의 제거 속도·온도, 상대 속도, 압력, 헤드 정지 시 기울어짐, 마른 패드, 수막, 컨디셔닝, 헤드 인터록, 구역 압력, 49점 계측과 판정, 모니터 갱신 주기, 막 색.
- `node --test tests/lab-3d-bundle.test.cjs`: 번들(`scene.js`)이 지금의 원본에서 만들어진 것인지.
- `node tools/check-browser.mjs`: 헤드리스 브라우저에서 실제 마우스와 키보드 입력으로 화면을 써 본다. 검사마다 스크립트 오류와 인터넷 요청이 없는지도 본다.
  - `lab-hover`: 부품 14개마다 제 카드가 뜨고 마우스가 벗어나면 사라진다(1600×1000, 1366×768 창). 로드 위치의 카드는 웨이퍼가 그 위에 없을 때 뜬다. 놓여 있는 동안에는 그 자리에서 웨이퍼의 카드가 뜬다.
  - `lab-operate`: 웨이퍼 장착 → 플래튼·스핀들 → 밸브 → 구역 조절기 → 컨디셔너 → 가압 → 연마 → 헤드 올리기 → 계측기까지 부품을 끌어서 한 번에 돌린다. 끄는 동안에는 값만 나오는 것, 장비 화면을 누르면 가까이 가는 것, 비상 정지도 본다.
  - `lab-panels`: 웨이퍼 두 장(정상 조건, 헤드를 돌리지 않은 조건)을 연마해 공정 계기가 올라오고 내려가는 것, 그래프와 요인의 마우스 올림 값, 계측 뒤 리포트가 열리는 것, 49점 지도의 마우스 올림 값, 기록 탭에서 웨이퍼를 골라 리포트를 여는 것, 닫은 뒤 다시 여는 것을 본다.
  - `home`: 홈 화면을 1920×1080, 1600×1000, 1366×768, 1024×768, 400×800 창에서 열어 옆으로 넘치지 않는 것, 두 그림과 두 설명의 높이가 맞는 것, 키보드 초점 테두리, 그림을 눌러 실험실로 들어가는 것을 본다.
  - `standalone`: 한 파일 빌드를 네트워크를 끊고 열어 홈 화면에 게임과 학습 실험실만 보이는 것(좁은 화면에서도), 학습 실험실 그림과 게임 설정 메뉴가 이 화면으로 오는 것, 되돌아가기 링크로 홈에 돌아오는 것, 파일 안에 재생 데이터가 없는 것을 본다.

명령으로 확인하지 못하는 것도 있다. 검사는 소프트웨어 렌더러에서 돈다(초당 3프레임). 실제 그래픽 카드에서의 속도와 손맛은 사람이 확인해야 한다. 화면이 느리면 렌더 해상도를 단계적으로 낮추게 해 두었는데, 이 동작은 실제 기기에서 확인하지 못했다.

## 아직 없는 것

리테이너 링 압력, 패턴 웨이퍼(단차·디싱), 종점 검출, 여러 장 연속 운전과 소모품 수명, 비용, 소리, 터치 화면(마우스 올림이 없어 부품 카드와 그래프 값을 볼 수 없음). 계측 기록은 저장하지 않는다. 시간 추이 그래프에는 표로 보는 방법이 없고(현재 값과 마우스 올림 값만), 어두운 화면 색은 만들지 않았다.
